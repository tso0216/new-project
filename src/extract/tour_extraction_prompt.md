# 旅行社行程 → 移動段（leg）抽取指示

你的任務：讀一份已解析的旅行社行程 JSON，判斷每天景點之間的「移動」，輸出成 JSON。
你負責**判斷**；格式與證據會由驗證腳本機械檢查，不合格會被退回。

## 輸入

`data/tour/colatour/itinerary/<PatternNo>.json`

- `source`、`trip`（`days`、`style_hint`：跟團／半自助／自由行）、`flights`
- `days[].stops[]`：`name`（項目名稱）、`visit_type`（入內參觀／下車拍照／行車經過／null）、`text`（該項目的原文說明）
- `days[].meals`、`days[].hotels`：與本任務無關，忽略

## 輸出

寫到 `data/tour/colatour/legs/<PatternNo>.json`，內容是**一個 JSON 陣列，每個元素是一筆 leg**（縮排 2 格，方便人讀）。
一筆 leg = 同一天內，從地點 A 移動到下一個地點 B。欄位（不多不少）：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `day` | int | 第幾天 |
| `seq` | int | 該天內的順序，從 1 連續遞增 |
| `from` / `to` | `{"name_raw": str, "visit_type": str\|null}` | `name_raw` 必須從原文逐字複製（不可自行加「站」「機場」等字）；`visit_type` 若該地點對應某個項目就照抄該項目的 `visit_type`，否則 null |
| `mode` | str | 只能是：`遊覽車` `步行` `電車` `纜車` `船` `飛機` `計程車` `自駕` `大眾運輸` `unspecified`。`電車` 含 JR、私鐵、地鐵、登山電車、特急、新幹線；`大眾運輸` 用於原文只寫「搭乘大眾交通工具」而沒說種類 |
| `mode_inferred` | bool | 原文對這一段**明寫**交通方式 → false；原文沒寫、由上下文推斷 → true（見下方規則）。`mode` 是 `unspecified` 時必須是 false |
| `vehicle_raw` | str\|null | 原文中的交通工具名稱，逐字（例：「箱根登山鐵道」「Laview列車」）。沒有就 null |
| `duration_min` | int\|null | 這一段**移動本身**的時間（分鐘）。只有原文明寫才填，見下方規則 |
| `cost_text` | str\|null | 原文明寫這一段的票價，逐字（例：「大人450日幣」）。沒有就 null |
| `evidence` | list[str] | 1～3 個**逐字**原文片段（每個 ≤120 字），支持這筆 leg 的地點順序、交通方式或時間 |
| `notes` | str | 有歧義或特殊處理時簡短說明（≤80 字），沒有就 "" |

## 判斷規則

1. **只根據這份 JSON 的文字判斷。** 不可用你對日本地理或交通的背景知識補地名、補交通方式、補時間。原文沒有的就填 null / unspecified。
2. **同一天內，依行程順序連接相鄰的地點。不跨天。** 每天的最後一站不必連到隔天。
3. **地點粒度**：
   - 一個項目名稱或說明裡列出多個地點（以「、」「～」「＋」「／」或文句列舉），拆成獨立地點，依原文順序連接。
   - 交通體驗類項目（如「箱根登山鐵道(箱根湯本～強羅)」）：端點是括號或說明中的站名，這一段本身就是一筆 leg，交通方式與時間照原文。
   - `visit_type` 是「行車經過」的項目（途經或夜宿區域），仍可當作端點，並保留 visit_type。
4. **不要建立與住宿、餐廳、贈品有關的 leg**（飯店、用餐地點、「贈送…」類項目不是地點）。所以第一天第一個景點之前若只有飯店，就不需要 leg。
   「自由活動」「約定的集合地點」也不是地點：**端點沒有具體地名的移動不建 leg**，不可借用相鄰項目當起點或終點（驗證腳本會擋名稱含「自由活動」「集合」的端點）。
5. **機場與航班**：原文寫搭機飛往某地，可建立 `from` 桃園、`to` 成田／羽田的 `飛機` leg（名稱逐字取自原文或 `flights`）；出關後由專車接送到第一個景點也是一筆 leg。回程同理。
6. **交通方式 `mode`**：
   - 原文對該段明寫（如「搭乘電車」「步行」「專車」「巴士」「纜車」）→ 照寫，`mode_inferred=false`。
   - 原文沒寫該段，且 `style_hint` 是「跟團」，行程中有寫專車／巴士／導遊帶領 → `遊覽車`，`mode_inferred=true`。
   - 半自助或自由行、原文沒寫 → `unspecified`。
   - 不確定就 `unspecified`，不要猜。
7. **`duration_min`**：
   - 只有原文明寫「這一段移動」的時間才填（例：「車程約1小時」「全程大約需40分鐘」「9分鐘的時間連結到…」）。「約1.5小時」→ 90。
   - **不算**：停留或參觀時間、營業時間、園區內設施的乘坐時間、與這一段無關的時間。
   - 原文是範圍（例：「約1～2小時」）→ null，並在 `notes` 說明。
   - `duration_min` 有值時，`evidence` 必須包含寫出該時間的原文片段。
8. **「自由活動」的日子**：原文沒有列出地點順序，這一天可以是 0 筆 leg，回報時說明。
9. **`evidence` 必須逐字**，可以省略前後文，但片段內不可改字。兩個相鄰景點若只有「項目順序」而沒有說明句，就用兩個項目名稱各自的原文當 evidence。

## 範例（僅示意格式）

```json
{"day": 2, "seq": 1, "from": {"name_raw": "箱根湯本", "visit_type": null}, "to": {"name_raw": "強羅", "visit_type": null}, "mode": "電車", "mode_inferred": false, "vehicle_raw": "箱根登山鐵道", "duration_min": 40, "cost_text": null, "evidence": ["箱根登山鐵道(箱根湯本～強羅)", "全程大約需40分鐘"], "notes": ""}
```

## 完成後

1. 執行 `.venv/bin/python src/extract/tour_observations.py check <PatternNo>`（在專案根目錄）。**修到沒有 ERROR 為止。**
2. WARNING 要逐條看：合理就保留（例如刻意略過的飯店、贈品），不合理就修。
3. 只寫你負責的那一個 legs 檔，不要改其他檔案，不要上網。
4. 最後回報（簡短）：leg 數、`mode` 分布（明寫／推斷各幾筆）、有 `duration_min` 的筆數，以及你做過的主要判斷與原文歧義（≤5 點）。
