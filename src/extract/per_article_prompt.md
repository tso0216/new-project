# 任務

使用者會給你一篇旅遊資料（旅行社行程頁或遊記），開頭的 `---` 區塊是 front matter（source、url、title、departure_months…）。
請找出文中出現的**景點（node）**，以及**實際發生的「景點 → 景點」移動（edge）**。

只根據這篇文章，不要用你自己的知識補資料；原文沒寫的欄位一律填 `null` 或 `[]`，不要猜。

輸出的 JSON 格式由系統限制，下面說明每個欄位怎麼填。示範（內容不是這篇文章的答案）：

```json
{
  "months": [9, 10, 11],
  "nodes": [
    {
      "poi_id": "P001",
      "poi_name": "淺草寺",
      "observations": [
        {"name_raw": "淺草寺", "visit_type": "入內參觀", "stay_min": 60, "as_area": false}
      ]
    },
    {
      "poi_id": "P002",
      "poi_name": "東京晴空塔",
      "observations": [
        {"name_raw": "晴空塔", "visit_type": "下車拍照", "stay_min": null, "as_area": false}
      ]
    }
  ],
  "edges": [
    {
      "from": "P001", "to": "P002",
      "mode": "自駕", "mode_inferred": true, "mode_basis": "旅行社跟團預設遊覽車",
      "vehicle": null, "duration_min": 20, "via": ["免稅店"], "day": 2
    }
  ]
}
```

---

# 什麼算景點（node）

**算景點**：神社寺廟、公園庭園、自然景觀、商圈老街、購物區（如原宿、代官山）、遊船纜車、地標展望、博物館、主題樂園、歷史古蹟、市場、動物園、溫泉街、目的地型餐飲（本身就是去處，如築地場外市場）。

**不算景點**（不建 node，不可當 `from`／`to`，只能放進 edge 的 `via`）：機場、車站（除非車站本身被當作觀光點介紹，例如「東京車站丸之內站舍」）、飯店／住宿、免稅店、一般用餐餐廳、休息站、集合地點、「溫暖的家」。

**同一站寫了多個景點就分開**：原文把幾個景點寫在同一站（例如「城崎海岸、門脇吊橋」「修善寺（獨鈷之湯、竹林小徑）」），每個景點各建一個 node，**不要自己判斷它們是不是同一個地方而合併**。括號裡如果只是說明（例如「箱根蘆之湖海盜船（富士山美景）」的「富士山美景」）就不是景點，不拆。

同一個景點在這篇文章裡只建**一個** node；它在文中每出現一次，就在該 node 的 `observations` 加一筆。

# 文章層級欄位

| 欄位 | 型別 | 規則 |
|---|---|---|
| `months` | integer[] | 旅行社行程 = 出團月份：front matter 有 `departure_months` 就取月份（`"2026/09"` → `9`），沒有就用內文寫的出團日期；遊記 = 文中寫的實際旅行月份（不是發文日期）。1–12、不重複；都沒寫就 `[]`。 |

# node 欄位規則

| 欄位 | 型別 | 規則 |
|---|---|---|
| `poi_id` | string | 這篇輸出內的編號，`"P"` + 3 位數，依景點在文章中第一次出現的順序從 `"P001"` 連號。edge 的 `from`／`to` 用它指向這個 node。 |
| `poi_name` | string | 景點的標準名稱：繁體中文、常見正式名稱，去掉括號附註和「參觀」「巡禮」「散策」等動作詞。原文只有日文／英文時，用通行的中文名。這個名稱會拿去 Google 地圖搜尋，所以要寫成搜尋得到的名稱。例：`海洋迪士尼樂園` → `東京迪士尼海洋`；`明治神宮參拜` → `明治神宮`。 |
| `observations` | object[] | 這個景點在文章中每出現一次記一筆，欄位見下。 |

`observations` 內的欄位：

| 欄位 | 型別 | 規則 |
|---|---|---|
| `name_raw` | string | 原文中指這個景點的**逐字**寫法（照抄，不改字、不轉簡繁、不去括號），必須能在原文中找到。同一站拆成多個景點時，填原文中指這個景點的那幾個字（例：「城崎海岸、門脇吊橋」拆出的門脇吊橋 → `"門脇吊橋"`）。 |
| `visit_type` | string \| null | 只能是 `"入內參觀"`（原文標明要進去參觀）、`"下車拍照"`（只下車拍照、短暫停留）、`"行車經過"`（車子經過、不停留）之一；原文沒標就 `null`。 |
| `stay_min` | integer \| null | 原文**明寫**在該景點停留的分鐘數，換算成整數（「約1小時」→ `60`）；沒寫就 `null`，不要自己估。 |
| `as_area` | boolean | 原文寫的是車站或商店（不是景點本身），但作者在那裡停留很久、實際是在逛那一區，所以你把它歸到對應的區域景點（`poi_name` 填該區域）→ `true`；原文寫的就是景點本身 → `false`。車站本身是景點時（如鎌倉高校前站的平交道）也填 `false`。 |

---

# edge 怎麼建

1. 按原文順序，把**同一天內相鄰的兩個景點**連成一條邊；中間的非景點放進 `via`。同一站拆出的多個景點也依原文順序相連。
2. **不跨天連邊**（前一天最後一個景點不連到隔天第一個景點）。
3. 只建「實際走過」的移動。以下**不建邊**：
   - 「自由活動」「敬請自理」日中列出的**建議**景點、「可前往…」「推薦…」等清單，因為沒有真的移動順序。
   - 景點介紹區、備選行程、「或」並列的替代方案。
   - 飯店介紹中的交通方式（飯店不是景點）。
4. 同一個景點在同一天連續出現（例如標題與介紹重複）只算一次，不要產生 A → A 的邊。
5. `edges` 依天數、再依當天原文順序輸出（程式會依這個順序編號）。

# edge 欄位規則

| 欄位 | 型別 | 規則 |
|---|---|---|
| `from` | string | 起點景點的 `poi_id`，必須是 `nodes` 裡定義過的。 |
| `to` | string | 終點景點的 `poi_id`，必須是 `nodes` 裡定義過的；不可與 `from` 相同。 |
| `mode` | string \| null | 只能是 `"大眾運輸"`（火車、地鐵、電車、公車、船班）、`"自駕"`（含旅行社遊覽車、租車）、`"走路"`、`null`。依下方「交通方式判斷」決定。 |
| `mode_inferred` | boolean | 原文**明寫**交通方式 → `false`；依下方推斷規則得到 → `true`；`mode` 為 `null` 時也填 `false`。 |
| `mode_basis` | string | 只能是：`"原文明寫"`、`"旅行社跟團預設遊覽車"`、`"同園區步行範圍"`、`"途經車站"`、`"遊記起訖點記成車站"`、`"原文未寫"`。 |
| `vehicle` | string \| null | 原文寫的具體交通工具（線名、車種、船名），逐字照抄（如 `"銀座線"`、`"江之島電鐵"`、`"JR山手線"`、`"遊覽車"`）；只寫「搭車」「搭電車」這類泛稱就照抄該詞；沒寫就 `null`。 |
| `duration_min` | integer \| null | 原文**明寫**的「移動」時間，換算成分鐘整數（「約1小時」→ `60`；「30~40分」→ 取中間值 `35`）。只算移動，不算停留、用餐、排隊。沒寫就 `null`，不要自己估。 |
| `via` | string[] | 這兩個景點之間被略過的**非景點**（車站、機場、飯店、免稅店、一般餐廳、休息站…），原文逐字名稱，依經過順序；沒有就 `[]`。景點本身不放進 `via`。 |
| `day` | integer | 第幾天（D1 → `1`）。遊記沒分天就全部填 `1`。 |

# 交通方式判斷（依序套用，命中第一條就停）

1. 原文明寫交通方式 → 填對應 `mode`，`mode_inferred: false`，`mode_basis: "原文明寫"`，`vehicle` 照抄。
2. 兩景點在同一園區／同一步行範圍（如淺草寺 → 仲見世通、同一座公園內）→ `"走路"`，`true`，`"同園區步行範圍"`。
3. 旅行社**跟團**行程（非自由行）且原文沒寫 → `"自駕"`，`true`，`"旅行社跟團預設遊覽車"`。
4. `via` 中有車站 → `"大眾運輸"`，`true`，`"途經車站"`。
5. 遊記中起點或終點被寫成車站名（如「到了鎌倉站後去鶴岡八幡宮」）→ `"大眾運輸"`，`true`，`"遊記起訖點記成車站"`。
6. 以上皆否 → `mode: null`，`mode_inferred: false`，`mode_basis: "原文未寫"`，`vehicle: null`。

# 輸出前自我檢查

- [ ] `poi_id` 從 `P001` 連號且不重複；兩個 node 的 `poi_name` 不相同。
- [ ] 每條 edge 的 `from`／`to` 都能在 `nodes` 找到，且 `from` ≠ `to`。
- [ ] `mode`、`mode_inferred`、`mode_basis` 三者符合「交通方式判斷」；`mode_basis` 是「原文未寫」時 `vehicle` 是 `null`。
- [ ] `name_raw` 能在原文中逐字找到。
- [ ] 沒有跨天的邊、沒有 A → A 的邊、沒有用自由活動建議清單建的邊。
